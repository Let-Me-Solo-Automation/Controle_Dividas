PASSO 01

Crie seu projeto gratuito.

  1. Abra o console do Firebase e entre com sua conta Google.
  2. Clique em Criar projeto ou Adicionar projeto. Nomeie como Marks e anote o ID que o Google gerar.
  3. Você pode deixar Google Analytics e recursos de Gemini desativados; o Marks não depende deles.
  4. Conclua a criação e confirme que o plano é Spark.
Não é necessário ativar o plano Blaze, adicionar cartão ou iniciar uma avaliação paga do Google Cloud. Use somente Authentication e Firestore nos passos abaixo.
PASSO 02

Ative o compartilhamento sem cadastro.

  1. Abra Authentication do projeto marks-79823 com a conta administradora.
  2. Em Método de login / Sign-in method → Adicionar novo provedor, escolha Anônimo / Anonymous.
  3. Escolha Ativar / Enable → Salvar / Save. Preserve E-mail/senha para contas que publicaram links antes. Se aparecer limpeza automática de usuários anônimos, deixe-a desativada.

Depois, recarregue o Marks e toque em Criar link sem vencimento. O acesso para atualizar e revogar é salvo neste navegador, sem preencher e-mail ou senha. Limpar os dados do navegador perde esse acesso; o backup dos acordos não o recupera. Abrir um link recebido não cria usuário.

Somente o administrador pode ativar esse provedor no console. A configuração pública do aplicativo não permite alterá-lo.
PASSO 03

Crie o banco de dados.

  1. Abra Criação / Build → Firestore Database → Criar banco de dados.
  2. Se houver escolha de edição, use Standard. Mantenha o banco padrão (default).
  3. Selecione a localização southamerica-east1 — São Paulo, se disponível.
  4. Escolha Modo de produção e crie o banco. Em seguida, publique as regras do próximo passo.

O Marks não precisa de Cloud Storage, Cloud Functions, SMS, backups gerenciados ou TTL pago.

PASSO 04

Publique as regras de acesso.

Atualização Marks: estas regras habilitam links sem vencimento e revogação definitiva. Ao atualizar as regras, recarregue o Marks. Para um link antigo, clique em Atualizar publicação para remover o vencimento.

  1. Na visão geral do projeto, abra o menu lateral Criação / Build → Firestore Database. Se estiver recolhido, use o botão ☰ no canto superior esquerdo. Na página do banco, abra a aba Regras / Rules.
  2. Copie as regras abaixo e substitua todo o texto do editor.
  3. Clique em Publicar / Publish.

Essas regras permitem publicar e alterar somente os acordos do proprietário. O destinatário consulta o acordo pelo link, sem editar. A listagem de todos os acordos é bloqueada.

PASSO 05

Registre o aplicativo web.

  1. Abra a engrenagem ao lado de Visão geral do projeto → Configurações do projeto → Geral.
  2. Em Seus aplicativos, clique no ícone </> Web. Se já existir um app web, você pode usar a configuração dele.
  3. Nomeie como Marks Web. Não precisa ativar Firebase Hosting; o site já está no GitHub Pages.
  4. Depois de registrar, escolha a opção Configuração / Config do SDK. Copie o objeto firebaseConfig com os valores do seu projeto.

Você não precisa executar os comandos de instalação mostrados pelo Firebase. O SDK já está instalado no Marks.

Como reconhecer a configuração pública
const firebaseConfig = {
  apiKey: "valor do seu projeto",
  authDomain: "seu-projeto.firebaseapp.com",
  projectId: "seu-projeto",
  storageBucket: "valor exibido pelo Firebase",
  messagingSenderId: "valor exibido pelo Firebase",
  appId: "valor exibido pelo Firebase"
};

O bloco acima é um exemplo. Copie os valores reais da tela do seu Firebase. O campo storageBucket pode aparecer no objeto, mas não precisamos ativar o serviço Storage.

Envie somente a configuração pública do app web. Não é necessário gerar ou enviar chave de conta de serviço, senha, token administrativo ou chave privada.
PASSO 06

Autorize o endereço do site.

  1. Volte a Authentication → Configurações / Settings → Domínios autorizados / Authorized domains.
  2. Clique em Adicionar domínio e use o endereço abaixo, sem https:// e sem o caminho do repositório. Preserve os domínios que já estiverem na lista.
let-me-solo-automation.github.io

ÚLTIMA ETAPA · NESTA CONVERSA

Envie o firebaseConfig para conectar o site.

Volte à conversa e cole o objeto público firebaseConfig do passo 5. Eu publico a conexão no GitHub e faço a verificação final.

Depois disso, no Marks, abra Seções → seu acordo → ícone de compartilhar, toque em Criar link sem vencimento, sem cadastro. A pessoa recebe uma página somente de leitura.

Até a configuração real ser conectada, o aplicativo continua local e o compartilhamento informa que o Firebase ainda não foi ativado.

Se algo não aparecer como descrito

  • Pediu cartão: volte e confirme que está no Spark e no Firestore Standard. Este projeto não depende do Blaze.
  • Banco já existe: use o banco padrão e siga para a aba Regras.
  • Não encontro o firebaseConfig: abra Configurações do projeto → Geral → Seus aplicativos → aplicativo web → Configuração do SDK.
  • Ainda pede configuração no Marks: isso é esperado antes de eu publicar o objeto enviado por você.

Existem cotas de uso. Mantendo o projeto no Spark, o serviço pode interromper operações ao atingir os limites gratuitos, em vez de habilitar cobrança automática.
